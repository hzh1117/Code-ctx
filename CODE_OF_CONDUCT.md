# Code of Conduct / 行为准则

## 中文

### 我们的承诺

Code-ctx 是一个源码公开、非商业使用的开发者工具项目。我们希望讨论保持直接、专业、可执行，帮助项目在安全性、可靠性和实用性上持续改进。

### 推荐行为

- 尊重他人，围绕事实、复现步骤、代码和文档讨论问题。
- 提交 issue 或 PR 时尽量提供环境、命令、日志、截图和最小复现。
- 对安全、许可证、密钥泄漏等高风险问题保持谨慎，不在公开讨论中粘贴敏感信息。
- 接受维护者对范围、优先级、商业使用边界和实现方式的判断。

### 不可接受的行为

- 骚扰、侮辱、歧视、人身攻击或反复干扰讨论。
- 未经允许公开他人的私人信息、凭据、API Key、Token、SSH Key、私有代码或私有项目文档。
- 规避或鼓励规避本项目的非商业许可限制。
- 故意提交恶意代码、后门、凭据泄漏、破坏性脚本或误导性的安全报告。

### 执行方式

维护者可以编辑、隐藏、关闭或删除违反本准则的评论、issue、pull request 或贡献。严重或重复违规可能导致被禁止参与项目。

### 报告

涉及安全、隐私、凭据或滥用的问题，请不要公开提交 issue。优先使用 GitHub 私有漏洞报告；如果不可用，请通过仓库所有者主页联系维护者。

## English

### Our Pledge

Code-ctx is a source-available developer tool for non-commercial use. We want discussions to stay direct, professional, and actionable so the project can improve its security, reliability, and usefulness.

### Expected Behavior

- Be respectful and discuss facts, reproduction steps, code, and documentation.
- Include environment details, commands, logs, screenshots, and minimal reproductions when opening issues or pull requests.
- Treat security, license, secret leakage, and credential topics carefully. Do not paste sensitive data in public discussions.
- Respect maintainer decisions about scope, priority, commercial-use boundaries, and implementation direction.

### Unacceptable Behavior

- Harassment, insults, discrimination, personal attacks, or repeated disruptive comments.
- Publishing private information, credentials, API keys, tokens, SSH keys, private code, or private project documentation without permission.
- Circumventing or encouraging others to circumvent the project's non-commercial license terms.
- Intentionally submitting malicious code, backdoors, leaked credentials, destructive scripts, or misleading security reports.

### Enforcement

Maintainers may edit, hide, close, or remove comments, issues, pull requests, or contributions that violate this code of conduct. Serious or repeated violations may result in a ban from the project.

### Reporting

For issues involving security, privacy, credentials, or abuse, do not open a public issue. Use GitHub private vulnerability reporting when available, or contact the maintainer through the repository owner profile.
